# Publishing 0.3.0 on Firefox Add-ons

Maintainer checklist for pushing 0.3.0 to the existing listing (add-on id `x-abuse-shield@downlz.github.io`). The general procedure is in [STORE.md](../STORE.md) section 6. The user-facing notes are [v0.3.0.md](v0.3.0.md).

0.3.0 adds search filtering and bounds the content script's memory. **The AI models are unchanged** (the toxicity model, and its trimmed version on phones), so nothing new goes on the model host and updating users don't download anything.

## 1. Build and test

1. `npm run release`. It checks every model file on the host against `public/models`, then writes:
   - `.output/release/x-abuse-shield-0.3.0.xpi`: upload this to AMO.
   - `.output/x-abuse-shield-0.3.0-sources.zip`: AMO asks for it because the build is minified.
2. Test the release files as shipped. Unzip the `.xpi` and the Chrome `.zip` to folders, then:

   ```sh
   npx tsx scripts/e2e-smoke.ts --firefox --extension=<unzipped .xpi folder>            # desktop
   npx tsx scripts/e2e-smoke.ts --firefox --mobile --extension=<unzipped .xpi folder>   # as a phone
   npx tsx scripts/e2e-smoke.ts --extension=<unzipped chrome .zip folder>               # Chrome
   ```

   From Firefox 159 the scripts need `MOZ_REMOTE_ALLOW_SYSTEM_ACCESS=1` to open extension pages; they set it themselves.
3. Worth a manual look on live x.com: **search results** (`/search?q=…`, Top and Latest) and a **hashtag page** are filtered, and **Settings → Where to filter → Search results** switches it off.

## 2. Upload to AMO

**Developer Hub → Manage My Submissions → X Abuse Shield → Upload New Version**

1. Upload `x-abuse-shield-0.3.0.xpi`. Compatibility: tick **Firefox** and **Firefox for Android**.
2. **Source code:** yes, upload `x-abuse-shield-0.3.0-sources.zip`.
3. **Release notes** (shown on the listing; plain text):

   ```
   • Search results and hashtag pages are now filtered too (on by default; Settings → Where to filter → Search results).
   • Steadier memory on long sessions: posts that have scrolled away are let go instead of being remembered until the tab closes. This matters most on phones.
   • Same AI model, nothing new to download.
   ```

4. **Notes to reviewer:**

   ```
   Node 22, npm. In the source folder:
     npm install
     WXT_BUNDLE_MODEL=false WXT_MODEL_URL=https://huggingface.co/downlz/x-abuse-shield-model/resolve/main/ npx wxt zip -b firefox
   Output: .output/x-abuse-shield-0.3.0-firefox.zip (same contents as the uploaded .xpi).
   public/ort/*.wasm is ONNX Runtime Web, copied from node_modules/onnxruntime-web by npm install (scripts/copy-ort.mjs).

   Changes since 0.2.6: search results are filtered; the content script's caches are bounded. No new permissions,
   no new network requests. The AI model is data, downloaded on first use (after the user clicks Download) from
   https://huggingface.co/downlz/x-abuse-shield-model: Horizon-Labs/multilingual-toxicity-small (Apache-2.0),
   and on Firefox for Android x-abuse-shield/multilingual-toxicity-lite (Apache-2.0, derived from it).
   ```

5. Submit. Once approved, installed copies update automatically.

## 3. After approval

1. Publish the GitHub release (Chrome/Brave files and checksums) from `main` after this branch is merged: `npm run release:publish -- --notes docs/releases/v0.3.0.md`. It tags `v0.3.0` at the current commit.
2. Check that the listing and the README badges show 0.3.0.

## Model host clean-up (optional)

The Hugging Face repo still holds the retired models' folders: `gravitee-io/distilbert-multilingual-toxicity-classifier/` and `x-abuse-shield/distilbert-toxicity-lite/`, uploaded while DistilBERT was being tried. No release uses them, and `npm run release` no longer checks them. Delete them (and their lines in the repo README) whenever convenient.
