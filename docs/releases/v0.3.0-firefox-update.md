# Publishing 0.3.0 on Firefox Add-ons

Maintainer checklist for pushing 0.3.0 to the existing listing (add-on id `x-abuse-shield@downlz.github.io`). The general procedure is in [STORE.md](../STORE.md) section 6; this covers what's different this time. The user-facing notes are [v0.3.0.md](v0.3.0.md).

## 1. Put the DistilBERT models on the model host

`npm run release` refuses to build until every model file is on the host, byte for byte.

- ✅ **Desktop DistilBERT** — uploaded 2026-11-09 (commit `5b550d5`), with the OpenRAIL++ note in the repo README (`afe0b62`).
- ✅ **Phone DistilBERT** (`x-abuse-shield/distilbert-toxicity-lite/`, 6 files, ~71 MB) — uploaded 2026-11-09 (commit `798781b`); the repo README lists it under OpenRAIL++, with the toxicity phone model (`279daa0`).
- ✅ **Checked:** all 22 files of the four model folders download from the host byte-identical to `public/models/`, with CORS headers, as `npm run release` checks.

If a phone model is rebuilt (`npm run model:trim -- distilbert`), upload it again at the same path:

```sh
hf upload downlz/x-abuse-shield-model public/models/x-abuse-shield/distilbert-toxicity-lite x-abuse-shield/distilbert-toxicity-lite
```

The toxicity model and its phone model on the host are unchanged.

## 2. Commit, build and test

1. Commit and push the branch, then merge it the usual way (release PR into `main`).
2. `npm run release`. It checks the host (all four model folders), then writes:
   - `.output/release/x-abuse-shield-0.3.0.xpi`: upload this to AMO.
   - `.output/x-abuse-shield-0.3.0-sources.zip`: AMO asks for it because the build is minified.
3. Test the release files as shipped. The automated Firefox tests work again on Firefox 159: it reads `MOZ_REMOTE_ALLOW_SYSTEM_ACCESS=1` from the environment instead of the old command-line flag, and both test scripts now set it. Unzip the `.xpi` to a folder, then:

   ```sh
   npx tsx scripts/e2e-smoke.ts --firefox --extension=<unzipped .xpi folder>            # desktop: 18 checks
   npx tsx scripts/e2e-smoke.ts --firefox --mobile --extension=<unzipped .xpi folder>   # as a phone: 24 checks
   npx tsx scripts/e2e-smoke.ts --extension=<unzipped chrome .zip folder>               # Chrome: 18 checks
   ```

   On 2026-11-09 the development builds passed all of them, plus the hosted phone run (26/26). That run confirmed a phone downloads only `x-abuse-shield/distilbert-toxicity-lite/`. Worth a manual look on live x.com: **search results** (`/search?q=…`, Top and Latest) and a **hashtag page** are filtered, and **Settings → Where to filter → Search results** switches it off.

## 3. Upload to AMO

**Developer Hub → Manage My Submissions → X Abuse Shield → Upload New Version**

1. Upload `x-abuse-shield-0.3.0.xpi`. Compatibility: tick **Firefox** and **Firefox for Android**.
2. **Source code:** yes, upload `x-abuse-shield-0.3.0-sources.zip`.
3. **Release notes** (shown on the listing; plain text):

   ```
   • Search results and hashtag pages are now filtered too (on by default; Settings → Where to filter → Search results).
   • A lighter default AI model on desktop: DistilBERT, a 140 MB download instead of 289 MB, 15 languages including Hindi and Hinglish. The previous 7-category model is still available under Settings → AI model → Model → Toxicity.
   • Phones get a lighter DistilBERT for English, Hindi and Hinglish: a 71 MB download instead of 93 MB. Posts in other languages are left to the word lists, or choose Toxicity for the previous phone model.
   • Steadier memory on long sessions: posts that have scrolled away are let go instead of being remembered until the tab closes.
   • After updating, click Download in the popup once (140 MB on a computer, 71 MB on a phone), or choose the Toxicity model to keep the one you already have.
   ```

4. **Notes to reviewer:**

   ```
   Node 22, npm. In the source folder:
     npm install
     WXT_BUNDLE_MODEL=false WXT_MODEL_URL=https://huggingface.co/downlz/x-abuse-shield-model/resolve/main/ npx wxt zip -b firefox
   Output: .output/x-abuse-shield-0.3.0-firefox.zip (same contents as the uploaded .xpi).
   public/ort/*.wasm is ONNX Runtime Web, copied from node_modules/onnxruntime-web by npm install (scripts/copy-ort.mjs).

   Changes since 0.2.6: search results are filtered; a second AI model, now the default, which the user picks in Settings.
   No new permissions. The AI models are data, downloaded on first use, only after the user clicks Download, from
   https://huggingface.co/downlz/x-abuse-shield-model:
     gravitee-io/distilbert-multilingual-toxicity-classifier (OpenRAIL++, LICENSE in its folder) — default
     x-abuse-shield/distilbert-toxicity-lite (OpenRAIL++, derived from the above, vocabulary trimmed) — default on Firefox for Android
     Horizon-Labs/multilingual-toxicity-small (Apache-2.0) — optional
     x-abuse-shield/multilingual-toxicity-lite (Apache-2.0, derived from the above) — optional on Firefox for Android
   The phone models are built from the originals by scripts/trim (npm run model:trim, npm run model:trim -- distilbert).
   ```

5. Submit. Reviews for an approved listing usually take a few days. Once approved, installed copies update automatically.

## 4. After approval

1. Publish the GitHub release (Chrome/Brave files and checksums): `npm run release:publish -- --notes docs/releases/v0.3.0.md`.
2. Check that the listing shows 0.3.0 and the README badge picks it up.
3. On a real phone with 0.2.6 installed: after the update, the popup asks for **Download (71 MB)**, then posts are scored. Worth checking `about:memory` (via remote debugging) after a long scroll; memory should level off rather than keep climbing.
