# Publishing 0.3.0 on Firefox Add-ons

Maintainer checklist for pushing 0.3.0 to the existing listing (add-on id `x-abuse-shield@downlz.github.io`). The general procedure is in [STORE.md](../STORE.md) section 6; this covers what's different this time. The user-facing notes are [v0.3.0.md](v0.3.0.md).

## 1. Put the DistilBERT model on the model host

`npm run release` refuses to build until every model file is on the host, byte for byte. The new model isn't there yet.

1. Build it, if `public/models/gravitee-io/` is missing: `npm run model:build -- distilbert`.
2. Upload the folder to the existing model repo, at the same path:

   ```sh
   hf upload downlz/x-abuse-shield-model public/models/gravitee-io/distilbert-multilingual-toxicity-classifier gravitee-io/distilbert-multilingual-toxicity-classifier
   ```

   (Older CLI: `huggingface-cli upload` with the same arguments.) That's 6 files, about 140 MB: `model.ort`, `config.json`, `tokenizer.json`, `tokenizer_config.json`, `LICENSE`, `NOTICE.md`.
3. In that repo's README, state that this folder is under **OpenRAIL++** (its `LICENSE` file), not Apache-2.0 like the rest. OpenRAIL++ asks anyone passing the model on to include its licence and use restrictions.
4. Check it: `https://huggingface.co/downlz/x-abuse-shield-model/resolve/main/gravitee-io/distilbert-multilingual-toxicity-classifier/config.json` should download.

The toxicity and phone models on the host are unchanged.

## 2. Commit, build and test

1. Commit and push the branch, then merge it the usual way (release PR into `main`).
2. `npm run release`. It checks the host (all three model folders), then writes:
   - `.output/release/x-abuse-shield-0.3.0.xpi`: upload this to AMO.
   - `.output/x-abuse-shield-0.3.0-sources.zip`: AMO asks for it because the build is minified.
3. Test the `.xpi` by hand. Since Firefox 159 the automated test (`npm run test:e2e:firefox`) can't open extension pages: Firefox now refuses WebDriver navigation to `moz-extension://` URLs. It stops at the first one and does so with the published 0.2.6 too, so it's the test harness, not the release. Until that's fixed, check in Firefox:
   - [ ] `about:debugging#/runtime/this-firefox` → **Load Temporary Add-on…** → the `.xpi`. The popup opens.
   - [ ] **Download (140 MB)** fetches the model from the host, and the status reaches *Ready*.
   - [ ] On x.com, an insult with no swear words is blurred, with a reason like "model: toxicity …", on Home, in replies and in **search results** (`/search?q=…`, Top and Latest) and on a **hashtag page**.
   - [ ] **Settings → Where to filter → Search results** off: search results are no longer filtered.
   - [ ] **Settings → AI model → Model → Toxicity**: loads the previous model; switching back works.
   - [ ] The **Hidden posts** page labels search entries "Search".
   - [ ] Optionally, with the 0.2.6 add-on installed and its model downloaded, load 0.3.0 over it. The popup asks for the 140 MB download, and choosing *Toxicity* loads without downloading.

   Chrome's automated test still works: `npm run test:e2e -- --extension=<unzipped chrome .zip>` (17/18 on this machine; the one failure is the 300 ms first-verdict limit, which the old model misses too).

## 3. Upload to AMO

**Developer Hub → Manage My Submissions → X Abuse Shield → Upload New Version**

1. Upload `x-abuse-shield-0.3.0.xpi`. Compatibility: tick **Firefox** and **Firefox for Android**.
2. **Source code:** yes, upload `x-abuse-shield-0.3.0-sources.zip`.
3. **Release notes** (shown on the listing; plain text):

   ```
   • Search results and hashtag pages are now filtered too (on by default; Settings → Where to filter → Search results).
   • A lighter default AI model on desktop: DistilBERT, a 140 MB download instead of 289 MB, 15 languages including Hindi and Hinglish. The previous 7-category model is still available under Settings → AI model → Model → Toxicity.
   • After updating on a computer, click Download (140 MB) in the popup once, or choose the Toxicity model to keep the one you already have.
   • Phones are unchanged: Firefox for Android keeps the light phone model and needs no new download.
   ```

4. **Notes to reviewer:**

   ```
   Node 22, npm. In the source folder:
     npm install
     WXT_BUNDLE_MODEL=false WXT_MODEL_URL=https://huggingface.co/downlz/x-abuse-shield-model/resolve/main/ npx wxt zip -b firefox
   Output: .output/x-abuse-shield-0.3.0-firefox.zip (same contents as the uploaded .xpi).
   public/ort/*.wasm is ONNX Runtime Web, copied from node_modules/onnxruntime-web by npm install (scripts/copy-ort.mjs).

   Changes since 0.2.6: search results are filtered; a second AI model, now the default, which the user picks in Settings.
   No new permissions. The AI models are data, downloaded on first use, only after the user clicks Download, from
   https://huggingface.co/downlz/x-abuse-shield-model:
     gravitee-io/distilbert-multilingual-toxicity-classifier (OpenRAIL++, LICENSE in its folder) — default
     Horizon-Labs/multilingual-toxicity-small (Apache-2.0) — optional
     x-abuse-shield/multilingual-toxicity-lite (Apache-2.0, derived from the above) — Firefox for Android
   ```

5. Submit. Reviews for an approved listing usually take a few days. Once approved, installed copies update automatically.

## 4. After approval

1. Publish the GitHub release (Chrome/Brave files and checksums): `npm run release:publish -- --notes docs/releases/v0.3.0.md`.
2. Check that the listing shows 0.3.0 and the README badge picks it up.
3. On a phone with 0.2.6 installed: after the update, the popup should not ask to download again, and posts are still scored by the phone model.
